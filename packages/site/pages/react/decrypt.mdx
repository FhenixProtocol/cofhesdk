# Decrypting in React

Three hooks decrypt a ciphertext handle in React, one per shape of work. All three go through the SDK client; none asks the user to sign anything, so a view never prompts for an ACP — it waits for one (see [ACPs in React](/react/acp)).

Declarative by default: a value a component renders, and a proof a page will send, are query hooks, so the cache, the ACP gate, retries and the activity panel come for free and the component re-renders as results arrive. The imperative `useCofheDecrypter` is for the two cases a query hook cannot express: the handles are only discovered inside the handler that uses them, or the result is an aggregate nobody renders per handle (a history to sum). Reaching for it because the decrypt happens "on click" is the wrong reason; flip `enabled` on click instead.

Every decrypt is a read. A handle maps to one plaintext forever, so a decrypt is a cached query keyed by the handle, never a mutation: a plaintext for the UI and a plaintext with the network's signature for a transaction are both decrypted once and kept. Only encryption (`useCofheEncrypt`) is a mutation — it makes a fresh ciphertext and proof on every call.

| Work                                      | Hook                                                                                                 |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| A value a component renders               | `useCofheDecrypt` (or `useCofheReadContractAndDecrypt` when the handle comes from one contract read) |
| A plaintext plus proof for a transaction  | `useCofheDecryptForTx`, mounted on the page that sends it                                            |
| Handles discovered in a handler, or a sum | `useCofheDecrypter`, from that handler                                                               |

## `useCofheDecrypt` — a value to render

A query. It runs only with a valid ACP, caches the plaintext under `[chainId, ctHash, utype, acpHash]`, persists what the user own ACP decrypts across reloads, and lists the decrypt in the activity panel.

```tsx
import { useCofheDecrypt } from '@cofhe/react';
import { FheTypes } from '@cofhe/sdk';

function Amount({ handle }: { handle: `0x${string}` }) {
  const { data, isFetching, error } = useCofheDecrypt(
    { input: { ctHash: handle, utype: FheTypes.Uint64 }, meta: { label: 'Vault balance' } },
    { staleTime: Infinity }
  );
  if (error) return <span>could not decrypt</span>;
  return <span>{isFetching ? '…' : data?.toString()}</span>;
}
```

Options: `chainId` (the chain the handle lives on, the connected chain by default), `acp` (decrypt with this ACP instead of the enclosing scope or the active one), `timeoutMs` (the decrypt's whole budget, 5 minutes by default), `onPoll`, `meta` and `context` for the activity panel, and any React Query option as the second argument.

## `useCofheDecrypter` — a job over many handles

The imperative counterpart: a hook whose `decryptForView` decrypts one handle on demand, for work a component does not render per value — a history to sum, a set of bids to reveal. Each call is the same query `useCofheDecrypt` would run: same key, same gate, same persistence, same activity row. A handle decrypted either way is decrypted once, and a cached plaintext comes back without a request.

```tsx
import { useState } from 'react';
import { useCofheDecrypter } from '@cofhe/react';
import { FheTypes } from '@cofhe/sdk';

type Bid = { id: string; eQuantity: `0x${string}`; ePaid: `0x${string}` };

function useRevealBids(bids: Bid[]) {
  const { decryptForView, isReady } = useCofheDecrypter();
  const [revealed, setRevealed] = useState<Map<string, { quantity: bigint; paid: bigint }>>(new Map());
  const [revealing, setRevealing] = useState(false);

  const revealAll = async () => {
    if (revealing || !isReady) return;
    setRevealing(true);
    const u64 = (ctHash: `0x${string}`, label: string) =>
      decryptForView({ ctHash, utype: FheTypes.Uint64 }, { meta: { label } });
    const next = new Map(revealed);
    await Promise.all(
      bids.map(async (bid) => {
        const [quantity, paid] = await Promise.all([u64(bid.eQuantity, `Bid ${bid.id}`), u64(bid.ePaid, `Bid ${bid.id}`)]);
        next.set(bid.id, { quantity, paid });
      })
    );
    setRevealed(next);
    setRevealing(false);
  };

  return { revealed, revealing, canReveal: isReady, revealAll };
}
```

Calls run at most `concurrency` at a time (4 by default), so `Promise.all` over the whole list is fine; the client's own `decryptConcurrency` cap (8 by default) sits above every caller. The hook's own options are `chainId`, `acp` and `concurrency`; each call takes `meta`, `context`, `onPoll`, `timeoutMs`, `staleTime` (`Infinity` by default), `retry` and `signal`.

`signal` is an `AbortSignal` for the job the call belongs to: when it fires, a call still waiting for a slot never starts, a request in flight is aborted, and the call rejects with a `CofheError` of code `Aborted`. Abort the job when the user navigates away, and nothing more is sent. A plaintext already in the cache is still returned, and a request already processing on the threshold network is not cancelled.

`isReady` is `false` without a client or a valid ACP; `decryptForView` then rejects with a `CofheError` (`ACPRequired` / `ACPExpired`) and sends nothing. The returned `acp` says why. A SNAPSHOT share that does not list the handle rejects with `ACPDenied`. A zero handle — a value never set on chain — resolves to the type's zero without a request.

It also returns `decryptForTx(ctHash, options)`: the same for a proof (see below), through the cache of `useCofheDecryptForTx`. It takes the options above plus `account`, `retry404TimeoutMs` and `acp: null` for a publicly allowed handle, which then needs only the client, not `isReady`. The zero handle rejects: there is nothing to prove.

## `useCofheDecryptForTx` — a plaintext with proof

A query around `client.decryptForTx`: the plaintext and the threshold network's signature over it, for a contract to verify (`FHE.verifyDecryptResult`). The contract checks only `(ctHash, value, signature)` — no nonce, no sender, no deadline — so the proof is a pure function of the handle, cached under `[chainId, ctHash, acpHash]` with `staleTime: Infinity`. Mount the hook on the page that will send the transaction and the proof is ready before the click:

```tsx
import { useCofheDecryptForTx } from '@cofhe/react';

function ClaimButton({ handle }: { handle: `0x${string}` }) {
  // `acp: null`: the contract allowed this handle publicly, no ACP is needed
  const { data: proof, isFetching, error } = useCofheDecryptForTx({ ctHash: handle, acp: null });
  const claim = () => {
    if (!proof) return;
    // … write the transaction with (proof.decryptedValue, proof.signature)
  };
  return <button onClick={claim} disabled={!proof || isFetching}>Claim</button>;
}
```

In a click handler that first discovers the handle, fetch the proof through the same cache with `useCofheDecrypter().decryptForTx(ctHash, { acp: null })`.

`acp` chooses the mode: `null` for a publicly allowed handle (`withoutACP()`, which then needs no ACP at all), omitted for the enclosing scope or the active ACP, or an ACP / stored hash. `chainId`, `account`, `onPoll`, `timeoutMs` and `retry404TimeoutMs` map onto the builder; `meta` and `context` and any React Query option work as on `useCofheDecrypt`. A proof decrypted with the user own ACP, or with none, persists across reloads; one decrypted with a shared ACP stays in memory and goes with the share.
