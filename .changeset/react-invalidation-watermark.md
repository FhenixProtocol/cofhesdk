Invalidation contexts become TTL WATERMARKS: block-awareness delivery is deterministic, not ordering luck. Previously a context was consumed by the first fetch that resolved under its prefix — reliable for the concurrent refetches an invalidation triggers, and pure timing luck for anything staggered: a query created after the outcome was known (`getPublish(orderId, newSeq)` after a fill, `getOrder(newId)` after a create), an `enabled` flip, a two-stage ids→batch read. Now `invalidateQueriesWithContext` stores a watermark that gates EVERY fetch under the prefix until it expires (`ttlMs` option, default 60s); entries expire by time, never by being read, and expired entries are pruned lazily (fixing the leak where an undelivered note lived forever). The store's prefix matching now mirrors react-query's partial-matching semantics (deep subset per segment), so an args-narrowed watermark like `args: [orderId]` reaches `getItem(orderId, seq)`-shaped keys exactly like the invalidation itself does. `consumeInvalidationContext` is removed from the public surface (nothing consumes on delivery any more); the once-per-block-probe cost repeats per gated fetch but resolves instantly in the same JSON-RPC batch once the node has caught up.
